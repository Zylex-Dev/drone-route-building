Аннотация — В данной статье представлена автоматизированная система планирования маршрутов полёта беспилотных летательных аппаратов для аэрофотосъёмки. Система реализована в виде веб-приложения с микросервисной архитектурой и использует алгоритм "газонокосилки" для построения маршрутов с заданным перекрытием снимков. Математическая модель рассчитывает параметры съёмки на основе характеристик камеры дрона. Интеграция с Open-Elevation API обеспечивает возможность учёта рельефа местности. Система поддерживает 6 популярных моделей дронов, рассчитывает детальные метрики миссии (время полёта, количество снимков, использование батареи) и экспортирует маршруты в форматы GeoJSON, KML и KMZ. Тестирование показало точность расчётов с погрешностью менее 2% и время генерации маршрута до 500 мс для территорий площадью до 10 км². Разработанная система с открытым исходным кодом может применяться для картографирования, мониторинга сельского хозяйства, инспекции инфраструктуры и других задач, требующих аэрофотосъёмки больших территорий.

Ключевые слова — беспилотные летательные аппараты, планирование маршрутов, аэрофотосъёмка, ГИС, алгоритм газонокосилки, веб-приложение, фотограмметрия, учёт рельефа.

ВВЕДЕНИЕ

В современных условиях беспилотные летательные аппараты (БПЛА) активно используются для решения широкого спектра задач: от картографирования территорий до мониторинга сельскохозяйственных угодий и инспекции инфраструктуры. Одной из ключевых задач при подготовке миссий аэрофотосъёмки является планирование оптимального маршрута полёта дрона, который обеспечит полное покрытие исследуемой территории с требуемым перекрытием снимков для последующей фотограмметрической обработки.

Актуальность задачи автоматизированного планирования маршрутов обусловлена несколькими факторами. Во-первых, ручное планирование маршрутов является трудоёмким процессом, требующим специальных знаний и навыков работы с геопространственными данными. Во-вторых, при ручном планировании высока вероятность ошибок в расчёте параметров съёмки, что может привести к недостаточному перекрытию снимков и невозможности построения качественной ортофотоплана или 3D-модели. В-третьих, отсутствие учёта характеристик конкретной модели дрона и его камеры приводит к неоптимальным параметрам миссии.

Существующие коммерческие решения для планирования маршрутов БПЛА, такие как DroneDeploy, Pix4Dcapture и UgCS, обладают широким функционалом, однако имеют ряд недостатков: платная модель распространения, закрытый исходный код, отсутствие веб-интерфейса или ограниченные возможности экспорта маршрутов в открытые форматы. Это создаёт потребность в разработке свободно распространяемого программного обеспечения с открытым исходным кодом.

Целью настоящего исследования является разработка автоматизированной системы планирования маршрутов полёта БПЛА для аэрофотосъёмки в виде веб-приложения с открытым исходным кодом, обеспечивающего точный расчёт параметров съёмки на основе технических характеристик дрона и учёт рельефа местности.

Для достижения поставленной цели необходимо решить следующие задачи:

1. Разработать математическую модель и алгоритм построения маршрута с заданным боковым и продольным перекрытием снимков на основе метода "газонокосилки".

2. Реализовать систему расчёта параметров съёмки (угол обзора камеры, размер кадра на местности, GSD) на основе технических характеристик камеры дрона.

3. Интегрировать данные о рельефе местности для расчёта абсолютной высоты полёта и обеспечения безопасности миссии.

4. Создать веб-интерфейс для интерактивного рисования территории съёмки на карте, визуализации маршрута и отображения детальных метрик миссии.

5. Разработать микросервисную архитектуру системы с разделением на компоненты: сервис аутентификации, сервис расчёта маршрутов, клиентское приложение и база данных.

6. Реализовать функции экспорта маршрутов в популярные форматы (GeoJSON, KML, KMZ) для использования в сторонних системах управления полётами.

По результатам анализа существующих подходов к планированию маршрутов БПЛА [1, 2] был выбран алгоритм "газонокосилки" (boustrophedon), обеспечивающий полное покрытие территории с минимальным количеством непродуктивных переходов между полосами съёмки. Для решения задачи была выбрана территория города Коломны Московской области в качестве тестового полигона.

АРХИТЕКТУРА СИСТЕМЫ

Разработанная система реализована на основе микросервисной архитектуры, что обеспечивает модульность, масштабируемость и независимое развитие отдельных компонентов. Архитектура состоит из четырёх основных компонентов, взаимодействующих через REST API:

1. PostgreSQL + PostGIS — реляционная система управления базами данных с расширением для работы с геопространственными данными. Используется для хранения информации о пользователях, их миссиях и геометрии территорий в формате GeoJSON. Применение PostGIS позволяет выполнять пространственные запросы и операции непосредственно на уровне базы данных.

2. Auth Service (Python/FastAPI) — микросервис аутентификации и управления миссиями. Реализован на базе асинхронного веб-фреймворка FastAPI, обеспечивающего высокую производительность и автоматическую генерацию OpenAPI документации. Использует JWT-токены для аутентификации пользователей, SQLAlchemy ORM совместно с GeoAlchemy2 для работы с геопространственными данными в PostGIS, и Pydantic для валидации входящих данных. Сервис предоставляет API для регистрации, авторизации пользователей и выполнения CRUD-операций над миссиями.

3. Route Service (Node.js/Express) — микросервис расчёта маршрутов полёта. Реализован на платформе Node.js с использованием веб-фреймворка Express.js. Основными библиотеками являются: Turf.js для геопространственных вычислений (пересечение геометрий, расчёт расстояний, построение bounding box), Joi для валидации параметров запроса, Winston для структурированного логирования всех этапов расчёта маршрута. Сервис получает от клиента полигон территории и параметры съёмки, выполняет расчёт маршрута с учётом характеристик выбранной модели дрона и возвращает результат в формате GeoJSON с детальными метриками миссии.

4. Client (Nginx + статические файлы) — клиентское веб-приложение, развёрнутое на веб-сервере Nginx. Интерфейс реализован с использованием современных веб-технологий: HTML5, CSS3, JavaScript (ES6+) и библиотеки Bootstrap 5 для адаптивного дизайна. Для работы с картами используется библиотека Leaflet.js с тайлами OpenStreetMap, плагин Leaflet.draw для рисования полигонов территорий, Leaflet.heat для визуализации тепловой карты рельефа. Интерактивные графики профиля высот реализованы с помощью библиотеки Plotly.js. Экспорт в формат KMZ осуществляется с использованием библиотеки JSZip.

Взаимодействие компонентов осуществляется следующим образом. Пользователь через веб-интерфейс (Client) рисует полигон территории на карте и задаёт параметры съёмки. Клиент отправляет запрос на Auth Service для проверки аутентификации, затем передаёт данные о территории и параметрах на Route Service. Сервис расчёта маршрутов выполняет вычисления и возвращает результат клиенту. Пользователь может сохранить миссию, отправив запрос на Auth Service, который записывает данные в PostgreSQL.

Все компоненты системы упакованы в Docker-контейнеры и оркестрируются с помощью Docker Compose, что обеспечивает простоту развёртывания системы на любом сервере с поддержкой Docker. Конфигурация включает health checks для контроля состояния сервисов, управление зависимостями запуска контейнеров и единую сеть для взаимодействия компонентов.

Преимущества микросервисной архитектуры для данной задачи:
- Независимое масштабирование компонентов (например, при высокой нагрузке на Route Service)
- Возможность использования разных технологических стеков для различных задач
- Упрощение тестирования и отладки отдельных компонентов
- Изоляция ошибок (сбой одного сервиса не приводит к отказу всей системы)

МАТЕМАТИЧЕСКАЯ МОДЕЛЬ И МЕТОДЫ РАСЧЁТА

Расчёт параметров камеры

Первым этапом планирования маршрута является расчёт параметров, характеризующих поле зрения камеры дрона. Горизонтальный угол обзора камеры (Field of View, FOV) рассчитывается на основе фокусного расстояния объектива и физического размера матрицы по формуле (1) [см. formulas.txt].

Аналогично рассчитывается вертикальный угол обзора по формуле (2) [см. formulas.txt], где вместо ширины матрицы используется её высота.

Расчёт покрытия на местности

Зная угол обзора камеры и высоту полёта, можно рассчитать размер области на земной поверхности, охватываемой одним снимком. Ширина охватываемой области рассчитывается по формуле (3) [см. formulas.txt], где используется тангенс половины угла обзора, что соответствует геометрии проецирования камеры на плоскость.

Длина охватываемой области рассчитывается аналогично по формуле (4) [см. formulas.txt].

Расчёт шага между полосами съёмки

Для обеспечения требуемого перекрытия снимков необходимо рассчитать эффективный шаг между полосами съёмки. Боковое перекрытие (sidelap) определяет степень перекрытия соседних полос съёмки и задаётся в долях от 0 до 1 (например, 0.3 соответствует 30% перекрытию). Эффективный шаг между полосами с учётом бокового перекрытия рассчитывается по формуле (5) [см. formulas.txt].

Продольное перекрытие (forward overlap) определяет степень перекрытия последовательных снимков вдоль полосы и также задаётся в долях. Эффективный шаг между снимками вдоль полосы рассчитывается по формуле (6) [см. formulas.txt]. Для фотограмметрических задач обычно требуется боковое перекрытие не менее 30% и продольное перекрытие не менее 70%.

Преобразование метров в градусы

Для выполнения геопространственных вычислений в географических координатах необходимо преобразовать расстояния из метров в градусы. Для широты преобразование является постоянным: 1 градус широты приблизительно равен 111 320 метрам в любой точке Земли.

Для долготы преобразование зависит от широты местности, так как меридианы сходятся к полюсам. Количество метров на градус долготы рассчитывается по формуле (7) [см. formulas.txt], где φ — широта центра территории съёмки.

Шаг между полосами в градусах долготы рассчитывается по формуле (8) [см. formulas.txt].

GSD (Ground Sample Distance)

Важным параметром качества аэрофотосъёмки является GSD — разрешение на местности, показывающее, какой размер объекта на земле соответствует одному пикселю на снимке. GSD рассчитывается по формуле (9) [см. formulas.txt], где ширина кадра на местности делится на разрешение изображения по горизонтали. Результат выражается в сантиметрах на пиксель.

Для достижения высокой точности фотограмметрических измерений обычно требуется GSD не более 2-3 см/пиксель, что достигается полётом на небольших высотах с камерами высокого разрешения.

АЛГОРИТМ ПОСТРОЕНИЯ МАРШРУТА

Алгоритм "газонокосилки" (Boustrophedon)

Для построения маршрута полёта, обеспечивающего полное покрытие территории, используется алгоритм "газонокосилки" (boustrophedon coverage path planning) [1, 2]. Алгоритм получил своё название по аналогии с движением газонокосилки, которая движется параллельными полосами, меняя направление в конце каждой полосы.

Алгоритм состоит из следующих этапов:

Этап 1. Получение полигона территории. Пользователь рисует полигон территории съёмки на интерактивной карте с помощью инструментов Leaflet.draw. Координаты вершин полигона передаются на сервер в формате массива точек с географическими координатами (широта, долгота).

Этап 2. Вычисление ограничивающего прямоугольника (bounding box). С помощью библиотеки Turf.js вычисляется минимальный прямоугольник, описывающий полигон территории. Прямоугольник задаётся четырьмя координатами: минимальная долгота, минимальная широта, максимальная долгота, максимальная широта.

Этап 3. Генерация вертикальных линий. Через bounding box проводятся вертикальные линии (параллельные меридианам) с шагом, равным рассчитанному эффективному шагу в градусах долготы. Каждая линия проходит от нижней границы bbox до верхней границы.

Этап 4. Нахождение пересечений линий с полигоном. Для каждой вертикальной линии с помощью функции lineIntersect библиотеки Turf.js определяются точки пересечения с границами полигона территории. Если линия пересекает полигон в двух или более точках, формируется отрезок маршрута от первой до последней точки пересечения.

Этап 5. Формирование полос полёта. Из полученных отрезков пересечений формируются полосы полёта, представляющие собой прямые линии, вдоль которых дрон будет выполнять съёмку.

Этап 6. Сортировка полос. Полосы сортируются по координате X (долготе) для обеспечения последовательного движения дрона с запада на восток (или с востока на запад).

Этап 7. Генерация waypoints вдоль полос. Вдоль каждой полосы генерируются точки съёмки (waypoints) с интервалом, равным рассчитанному продольному шагу. Это обеспечивает требуемое продольное перекрытие снимков.

Этап 8. Зигзагообразное соединение полос. Для минимизации непродуктивных переходов между полосами используется зигзагообразное соединение: дрон проходит нечётные полосы снизу вверх, а чётные — сверху вниз. Это достигается реверсированием массива waypoints для каждой второй полосы.

Детальный псевдокод алгоритма представлен ниже:

АЛГОРИТМ BuildFlightRoute(polygon, altitude, overlapSide, overlapForward, droneModel)
  ВХОД: polygon - полигон территории,
        altitude - высота полёта (м),
        overlapSide - боковое перекрытие (доля 0-1),
        overlapForward - продольное перекрытие (доля 0-1),
        droneModel - модель дрона
  ВЫХОД: массив координат waypoints с детальными метриками
  
  1. camera ← getDroneCamera(droneModel)
  2. FOVh ← calculateHorizontalFOV(camera.focalLength, camera.sensorWidth)
  3. FOVv ← calculateVerticalFOV(camera.focalLength, camera.sensorHeight)
  4. Wground ← 2 * altitude * tan(FOVh/2)
  5. Lground ← 2 * altitude * tan(FOVv/2)
  6. Slateral ← Wground * (1 - overlapSide)
  7. Sforward ← Lground * (1 - overlapForward)
  8. bbox ← calculateBoundingBox(polygon)
  9. centerLat ← (bbox.minLat + bbox.maxLat) / 2
  10. mlng ← 111320 * cos(centerLat * PI / 180)
  11. Sdeg ← Slateral / mlng
  12. flightLines ← []
  13. lineCount ← 0
  14. ДЛЯ x ОТ bbox.minLng ДО bbox.maxLng С ШАГОМ Sdeg
       15. lineCount ← lineCount + 1
       16. ЕСЛИ lineCount > MAX_FLIGHT_LINES (1000) ТО
            17. ВЕРНУТЬ ОШИБКУ "Превышен лимит полос"
       18. line ← createVerticalLine(x, bbox.minLat, bbox.maxLat)
       19. intersections ← findIntersections(line, polygon)
       20. ЕСЛИ intersections.length >= 2 ТО
            21. sortByLatitude(intersections)
            22. segment ← createSegment(intersections[0], intersections[last])
            23. flightLines.push(segment)
  24. sortLinesByLongitude(flightLines)
  25. waypoints ← []
  26. segments ← []
  27. ДЛЯ i ОТ 0 ДО flightLines.length - 1
       28. startPoint ← flightLines[i].coordinates[0]
       29. endPoint ← flightLines[i].coordinates[1]
       30. lineWaypoints ← generateWaypointsAlongLine(startPoint, endPoint, Sforward)
       31. ЕСЛИ i % 2 == 1 ТО
            32. reverse(lineWaypoints)  // Зигзагообразное движение
       33. ЕСЛИ waypoints.length > 0 ТО
            34. transitionSegment ← {type: 'transition', coordinates: [waypoints[last], lineWaypoints[0]]}
            35. segments.push(transitionSegment)
       36. workSegment ← {type: 'work', coordinates: lineWaypoints}
       37. segments.push(workSegment)
       38. waypoints.concat(lineWaypoints)
  39. metrics ← calculateMissionMetrics(waypoints, polygon, droneModel, altitude)
  40. routeGeoJSON ← createGeoJSON(waypoints, segments, metrics)
  41. ВЕРНУТЬ routeGeoJSON
КОНЕЦ АЛГОРИТМА

Функция generateWaypointsAlongLine выполняет интерполяцию точек вдоль линии:

ФУНКЦИЯ generateWaypointsAlongLine(startPoint, endPoint, spacingMeters)
  1. lineLength ← calculateDistance(startPoint, endPoint)  // в метрах
  2. ЕСЛИ lineLength <= spacingMeters ТО
       3. ВЕРНУТЬ [startPoint, endPoint]
  4. numPoints ← ceil(lineLength / spacingMeters)
  5. waypoints ← []
  6. ДЛЯ i ОТ 0 ДО numPoints
       7. fraction ← i / numPoints
       8. point ← interpolate(startPoint, endPoint, fraction)
       9. waypoints.push(point)
  10. ВЕРНУТЬ waypoints

Оптимизация и защита от больших территорий

Для обеспечения стабильности работы системы и защиты от перегрузки при обработке больших территорий реализованы следующие механизмы ограничения:

1. Ограничение максимального количества полос полёта — 1000 линий. При превышении этого лимита алгоритм прерывает выполнение и возвращает ошибку с рекомендацией увеличить высоту полёта или уменьшить площадь территории.

2. Ограничение времени выполнения алгоритма — 30 секунд. В цикле генерации полос выполняется проверка времени выполнения, и при превышении лимита расчёт прерывается.

3. Ограничение площади территории — 10 км². Перед началом расчёта маршрута проверяется площадь полигона с помощью функции turf.area(). Также установлена минимальная площадь 100 м² для предотвращения обработки слишком малых территорий.

4. Валидация входных параметров с помощью библиотеки Joi. Проверяются диапазоны допустимых значений: высота полёта 5-400 м, боковое перекрытие 10-95%, продольное перекрытие 50-95%, количество точек полигона 3-1000.

5. Логирование прогресса выполнения алгоритма. С помощью библиотеки Winston ведётся детальное логирование каждого этапа расчёта с указанием времени выполнения, что позволяет отслеживать производительность и выявлять узкие места.

Интеграция данных о рельефе местности

Для обеспечения безопасности полёта и возможности планирования миссий в гористой местности реализована интеграция с Open-Elevation API [9] для получения данных о высотах точек маршрута.

При включении опции "Учитывать рельеф местности" система выполняет следующие действия:

1. Получение сетки высот для всей территории. Bounding box территории разбивается на регулярную сетку с адаптивной плотностью (10-20 точек на сторону в зависимости от площади). Для каждой точки сетки запрашивается высота над уровнем моря через Open-Elevation API.

2. Получение профиля высот вдоль маршрута. Для визуализации профиля высот запрашиваются высоты точек, равномерно распределённых вдоль маршрута (не более 500 точек для оптимизации размера ответа).

3. Расчёт абсолютной высоты полёта. Определяются максимальная и минимальная высоты рельефа на территории. Абсолютная высота полёта рассчитывается по формуле (10) [см. formulas.txt], что гарантирует пролёт дрона на заданной относительной высоте над наивысшей точкой рельефа.

4. Визуализация данных. На карте отображается тепловая карта рельефа с использованием Leaflet.heat, где более высокие участки показаны красным цветом, низкие — синим. Пользователю доступен интерактивный график профиля высот, построенный с помощью Plotly.js.

Для территорий с плоским рельефом (перепад высот менее 5 м) система выдаёт соответствующее уведомление и отключает адаптацию высоты полёта.

РАСЧЁТ МЕТРИК МИССИИ

Система автоматически рассчитывает детальные метрики миссии, необходимые для планирования и оценки выполнимости полёта.

Площадь покрытия рассчитывается с помощью функции turf.area() библиотеки Turf.js, которая вычисляет площадь полигона в квадратных метрах с учётом кривизны Земли. Результат преобразуется в квадратные километры для удобства восприятия.

Общая длина маршрута вычисляется как сумма расстояний между последовательными waypoints. Для расчёта расстояний используется функция turf.distance() с указанием единиц измерения в метрах. Функция учитывает сферическую форму Земли и использует формулу гаверсинуса для точного расчёта расстояний по геодезической линии.

Расчётное время полёта определяется по формуле (11) [см. formulas.txt], где учитывается время на перелёт между точками и время на стабилизацию и выполнение съёмки в каждой точке. Крейсерская скорость дрона берётся из технических характеристик выбранной модели. Время на выполнение съёмки в каждой точке принято равным 2 секундам, что включает стабилизацию дрона, автофокусировку камеры и непосредственно съёмку.

Количество снимков равно количеству waypoints в маршруте, так как в каждой точке маршрута выполняется одна фотография.

Требуемая память для хранения снимков рассчитывается исходя из предположения, что один RAW-снимок занимает приблизительно 20 МБ. Общий объём вычисляется умножением количества снимков на размер одного файла с преобразованием в гигабайты.

Использование батареи вычисляется по формуле (12) [см. formulas.txt], где расчётное время полёта сравнивается с максимальным временем полёта дрона, умноженным на коэффициент безопасности 0.8 (80% ёмкости батареи). Это позволяет оценить, хватит ли заряда батареи для выполнения миссии за один полёт или потребуется разбиение на несколько сегментов.

Все рассчитанные метрики включаются в ответ сервера в структурированном виде и отображаются в веб-интерфейсе в виде информационных панелей с иконками и цветовой индикацией (например, использование батареи более 90% выделяется красным цветом как предупреждение).

РЕАЛИЗАЦИЯ ВЕБ-ПРИЛОЖЕНИЯ

Технологии фронтенда

Клиентская часть приложения реализована с использованием современных веб-технологий без применения тяжёлых фреймворков, что обеспечивает быструю загрузку и отзывчивость интерфейса.

Основу составляют стандартные технологии: HTML5 для структуры страницы, CSS3 для стилизации с использованием flexbox и grid для адаптивной вёрстки, JavaScript (стандарт ES6+) для реализации логики приложения.

Для построения пользовательского интерфейса используется Bootstrap 5 — популярный CSS-фреймворк, обеспечивающий адаптивность интерфейса для различных размеров экранов и унифицированный внешний вид компонентов (кнопки, формы, модальные окна).

Картографический функционал реализован на базе библиотеки Leaflet.js [6] — легковесной JavaScript-библиотеки для работы с интерактивными картами. В качестве источника тайлов используется OpenStreetMap [8] — свободная карта мира, созданная сообществом. Для рисования полигонов территорий применяется плагин Leaflet.draw, предоставляющий удобные инструменты для создания, редактирования и удаления геометрических объектов на карте.

Визуализация тепловой карты рельефа реализована с помощью плагина Leaflet.heat, который строит heat map на основе массива точек с весами (высотами). Интерактивные графики профиля высот создаются с использованием библиотеки Plotly.js, обеспечивающей возможность масштабирования, панорамирования и отображения детальной информации при наведении курсора.

Экспорт маршрутов в формат KMZ (сжатый KML) осуществляется с помощью библиотеки JSZip, которая позволяет создавать ZIP-архивы непосредственно в браузере без отправки данных на сервер.

Архитектура клиентского кода построена по модульному принципу с разделением на функциональные модули: map-init.js (инициализация карты), route-builder.js (построение маршрута), ui-controller.js (управление интерфейсом), export-manager.js (экспорт в различные форматы), auth.js (аутентификация), mission-manager.js (управление миссиями), flight-simulation.js (симуляция полёта), terrain-visualization.js (визуализация рельефа).

Технологии бэкенда

Сервис расчёта маршрутов (Route Service) реализован на платформе Node.js с использованием минималистичного веб-фреймворка Express.js. Основной файл index.js содержит логику обработки HTTP-запросов, валидации параметров и вызова функций расчёта маршрута.

Библиотека Turf.js [7] является ключевым инструментом для выполнения геопространственных операций. Используются следующие функции: turf.polygon() для создания полигона из массива координат, turf.bbox() для вычисления bounding box, turf.lineString() для создания линий, turf.lineIntersect() для нахождения пересечений, turf.distance() для расчёта расстояний, turf.area() для вычисления площади.

Валидация входящих данных выполняется с помощью библиотеки Joi, позволяющей декларативно описывать схемы валидации. Определена схема calculateRouteSchema, включающая проверку типов данных, диапазонов значений и обязательности полей. При обнаружении ошибок валидации клиенту возвращается детальное описание всех проблем.

Структурированное логирование реализовано с использованием библиотеки Winston. Настроены два логгера: app (для общих событий приложения) и calculation (для детального логирования процесса расчёта маршрутов). Логи записываются в файлы с ротацией и выводятся в консоль в формате JSON с метками времени, уровнями важности и контекстной информацией. Каждому запросу присваивается уникальный requestId для трассировки всех операций в рамках одного запроса.

Юнит-тестирование выполняется с помощью фреймворка Jest. Покрытие тестами включает проверку корректности расчёта параметров камеры, генерации waypoints, обработки граничных случаев и валидации входных данных.

Сервис аутентификации (Auth Service) реализован на языке Python с использованием асинхронного веб-фреймворка FastAPI [10]. Асинхронная архитектура обеспечивает высокую производительность при обработке множества одновременных запросов.

SQLAlchemy ORM используется для работы с базой данных PostgreSQL. Расширение GeoAlchemy2 добавляет поддержку геопространственных типов данных PostGIS, позволяя хранить полигоны территорий и маршруты в нативном формате базы данных. Используется асинхронный драйвер AsyncPG для неблокирующего взаимодействия с БД.

Валидация данных и автоматическая генерация схем API осуществляется с помощью Pydantic — библиотеки для валидации данных на основе type hints Python. Определены схемы для всех API endpoints, что обеспечивает строгую типизацию и автоматическую проверку входящих данных.

Аутентификация пользователей реализована с использованием JWT-токенов (JSON Web Tokens). При успешной авторизации сервер генерирует токен со сроком действия 7 дней, который клиент сохраняет в localStorage браузера и передаёт в заголовке Authorization при каждом запросе к защищённым endpoints.

База данных

PostgreSQL 16 с расширением PostGIS используется для хранения всех данных системы. PostGIS добавляет поддержку географических объектов, позволяя выполнять пространственные запросы, индексацию по геометрии и применять географические функции непосредственно на уровне SQL.

Схема базы данных включает две основные таблицы: users (хранение информации о пользователях) и missions (хранение миссий). Таблица missions содержит следующие поля: id (UUID), user_id (внешний ключ на users), name (название миссии), description (описание), status (статус: draft, active, completed, archived), flight_altitude, desired_overlap, forward_overlap, drone_model, shooting_type, enable_terrain_following, territory (геометрия полигона территории типа GEOMETRY(Polygon, 4326)), route_geojson (маршрут в формате JSONB), created_at, updated_at.

Использование типа GEOMETRY для поля territory позволяет применять пространственные индексы (GiST) для быстрого поиска миссий, пересекающихся с заданной областью. Хранение маршрута в формате JSONB обеспечивает эффективное хранение структурированных данных с возможностью индексации и запросов к вложенным полям.

3. Настройка параметров полёта через удобную боковую панель: высота полёта (5-400 м), боковое перекрытие (10-95%), продольное перекрытие (50-95%), выбор модели дрона из 6 доступных вариантов, включение/выключение учёта рельефа.

6. Отображение детальных метрик миссии в трёхуровневой иерархии панелей: базовая информация (всегда видна), параметры покрытия (сворачиваемая секция), технические параметры (скрытая по умолчанию секция для экспертов).

7. Экспорт маршрута в три формата: GeoJSON (для ГИС-систем и веб-приложений), KML (для Google Earth и других картографических сервисов), KMZ (сжатый KML в ZIP-архиве).

8. Сохранение миссий в базу данных с возможностью указания названия и описания. Личный кабинет пользователя содержит список всех сохранённых миссий с возможностью загрузки, редактирования и удаления.

9. Симуляция полёта с анимацией движения дрона вдоль маршрута. Пользователь может запускать, останавливать симуляцию, изменять скорость воспроизведения (1x, 5x, 10x), перематывать с помощью слайдера timeline. Во время симуляции отображается текущая позиция дрона, зона покрытия камеры, прогресс выполнения миссии и затраченное время.

10. Интеграция прогноза погоды через OpenWeatherMap API с отображением текущих условий (температура, скорость ветра, облачность) в виде статус-бара в нижней части экрана. При неблагоприятных условиях (сильный ветер, осадки) выводятся предупреждения.

11. Интерактивный профиль рельефа в виде модального окна с детальным графиком высот вдоль маршрута, статистикой (максимальная/минимальная высота, перепад), анализом типа рельефа (плоский, холмистый, гористый) и рекомендациями по высоте полёта.

Тестирование системы

Для проверки корректности работы системы и оценки её производительности было проведено тестирование на трёх территориях различной площади с разными параметрами съёмки.

Тест 1: Небольшая территория (городской парк). Площадь территории составила 0.25 км² (500×500 м). Результаты: сгенерировано 48 waypoints, общая длина маршрута 2.1 км, расчётное время полёта 5.2 минуты, использование батареи 16%, требуется 1 полёт. GSD составил 1.9 см/пиксель, что обеспечивает высокую детализацию для создания ортофотоплана.

Для проверки корректности математической модели были выполнены сравнения рассчитанных параметров с табличными значениями производителей дронов и результатами расчётов в профессиональных программах планирования миссий.

GSD (разрешение на местности): Рассчитанные значения GSD для различных моделей дронов и высот полёта сравнивались с таблицами производителей. Погрешность составила менее 2%, что обусловлено округлением параметров камеры и упрощением модели проецирования.

Фактическое перекрытие снимков: С помощью визуализации зон покрытия камеры на карте было проверено, что фактическое перекрытие соседних снимков соответствует заданному значению с точностью ±1%. Небольшое отклонение связано с дискретностью размещения waypoints и округлением координат.

Покрытие территории: Визуальная проверка построенных маршрутов показала 100% покрытие заданной территории при отсутствии no-fly зон. Алгоритм корректно обрабатывает невыпуклые полигоны сложной формы, включая полигоны с вогнутыми участками.

Производительность

Производительность системы оценивалась по следующим метрикам:

Время построения маршрута: Для территории площадью 0.25 км² время расчёта составило 50-80 мс, для 2.5 км² — 180-250 мс, для 8.5 км² — 420-500 мс. Время зависит от площади территории, заданного перекрытия (меньшее перекрытие — меньше полос) и сложности формы полигона.

Время получения данных о рельефе: При включённой опции учёта рельефа для территории 2.5 км² запрос к Open-Elevation API и обработка данных занимают 1.2-1.8 секунды. Для оптимизации используется адаптивная плотность сетки точек и ограничение максимальной площади территории для запроса elevation (50 км²).

Размер ответа API: Размер JSON-ответа сервера зависит от количества waypoints. Для маршрута с 50 точками размер составляет около 50 КБ, для 300 точек — 180 КБ, для 900 точек — 520 КБ. При включении данных о рельефе размер увеличивается на 30-50% из-за массивов elevation profile и grid.

Практическое применение

Разработанная система может применяться для решения следующих задач:

1. Планирование миссий аэрофотосъёмки для фотограмметрии: создание ортофотопланов, цифровых моделей рельефа и 3D-моделей местности. Система обеспечивает требуемое перекрытие снимков (обычно 70-80% продольное и 30-60% боковое) для корректной работы алгоритмов Structure from Motion.

2. Картографирование сельскохозяйственных угодий: мониторинг состояния посевов, оценка ущерба от стихийных бедствий, планирование агротехнических мероприятий. Регулярные аэрофотосъёмки позволяют отслеживать динамику развития растений и оперативно выявлять проблемные участки.

3. Мониторинг строительных объектов: контроль хода строительства, измерение объёмов земляных работ, инспекция качества выполнения работ. Аэрофотосъёмка обеспечивает документирование состояния объекта на различных этапах строительства.

4. Инспекция линейных объектов инфраструктуры: линии электропередач, трубопроводы, дороги, железнодорожные пути. Автоматизированное планирование маршрутов вдоль протяжённых объектов позволяет эффективно выполнять регулярные инспекции для выявления дефектов и повреждений.

5. Экологический мониторинг: оценка состояния лесных массивов, контроль береговой эрозии, мониторинг последствий наводнений и других стихийных бедствий. Аэрофотосъёмка больших территорий с высоким разрешением позволяет получить актуальную информацию о состоянии природных объектов [3, 4].

ЗАКЛЮЧЕНИЕ

В ходе проведённого исследования была разработана автоматизированная система планирования маршрутов полёта беспилотных летательных аппаратов для аэрофотосъёмки. Система реализована в виде веб-приложения с микросервисной архитектурой и включает следующие основные компоненты:

1. Математическая модель расчёта параметров съёмки на основе технических характеристик камеры дрона, включающая вычисление угла обзора камеры, размера кадра на местности, GSD и эффективного шага между полосами съёмки с учётом заданного перекрытия.

2. Алгоритм построения маршрута по методу "газонокосилки" с заданным боковым и продольным перекрытием снимков, обеспечивающий полное покрытие территории с минимальным количеством непродуктивных переходов.

3. Интеграция данных о рельефе местности с использованием Open-Elevation API для расчёта абсолютной высоты полёта над максимальной точкой рельефа, визуализации тепловой карты высот и построения профиля рельефа вдоль маршрута.

4. Веб-интерфейс на основе Leaflet.js для интерактивного рисования территории на карте, визуализации маршрута с зонами покрытия камеры, отображения детальных метрик миссии и управления сохранёнными миссиями.

5. Система расчёта метрик миссии, включающая площадь покрытия, длину маршрута, время полёта, количество снимков, требуемую память и использование батареи, что позволяет оценить выполнимость миссии и необходимость разбиения на несколько полётов.

Основные достижения работы:

- Реализована автоматизация процесса планирования маршрутов с учётом технических характеристик шести популярных моделей дронов (DJI Matrice 30T, Mavic 3, Phantom 4 Pro, Air 2S, Mini 3 Pro, Autel EVO Lite+).

- Достигнута точность расчёта параметров съёмки с погрешностью менее 2% по сравнению с табличными значениями производителей.

- Обеспечена поддержка территорий площадью от 100 м² до 10 км² с автоматической защитой от перегрузки системы.

- Время построения маршрута не превышает 500 мс для территорий площадью до 10 км², что обеспечивает комфортную работу пользователя.

- Система распространяется с открытым исходным кодом на платформе GitHub, что позволяет сообществу использовать, модифицировать и развивать проект.

Полученные результаты наглядно демонстрируют возможности применения геопространственных алгоритмов и современных веб-технологий для автоматизации планирования миссий БПЛА. Разработанная система значительно упрощает процесс подготовки к аэрофотосъёмке, предоставляя пользователю детальные метрики миссии, визуализацию маршрута и возможность экспорта в популярные форматы для использования в различных системах управления полётами.

Направления дальнейшего развития системы:

1. Интеграция автоматических зон запрета полётов (no-fly zones) на основе данных авиационных служб и реестров аэродромов для обеспечения безопасности полётов и соблюдения законодательных требований.

2. Реализация адаптивной оптимизации направления полос на основе анализа формы территории с целью минимизации количества полос и общей длины маршрута.

3. Автоматическое разбиение маршрута на сегменты с учётом ограничений батареи дрона и указанием промежуточных точек смены батареи.

4. Интеграция с протоколами DroneKit и MAVLink для прямой загрузки миссий на дрон через USB или Wi-Fi подключение без необходимости экспорта и импорта файлов.

5. Применение методов машинного обучения для предсказания оптимальных параметров съёмки на основе анализа успешно выполненных миссий и характеристик территории.

Разработанная система может быть использована для картографирования, мониторинга сельского хозяйства, инспекции инфраструктуры, экологического мониторинга и других задач, требующих аэрофотосъёмки больших территорий с высоким разрешением и точным перекрытием снимков.

AUTOMATED FLIGHT ROUTE PLANNING SYSTEM FOR UNMANNED AERIAL VEHICLES FOR AERIAL PHOTOGRAPHY

[Author Name in Latin]
[Organization in English]
[Department in English]
[City, Country]
[email@example.com]

Abstract — This paper presents an automated system for planning flight routes of unmanned aerial vehicles (UAVs) for aerial photography. The system is implemented as a web application with microservice architecture and uses the "lawnmower" algorithm to build routes with specified image overlap. The mathematical model calculates shooting parameters based on drone camera characteristics, including field of view, ground coverage, and ground sample distance (GSD). Integration with Open-Elevation API provides terrain following capabilities by calculating absolute flight altitude above the highest terrain point. The system supports 6 popular drone models (DJI Matrice 30T, Mavic 3, Phantom 4 Pro, Air 2S, Mini 3 Pro, Autel EVO Lite+), calculates detailed mission metrics including flight time, number of photos, battery usage, and exports routes to GeoJSON, KML, and KMZ formats. The microservice architecture consists of four components: PostgreSQL with PostGIS for geospatial data storage, Python/FastAPI authentication service with JWT tokens, Node.js/Express route calculation service using Turf.js library, and Nginx-based client with Leaflet.js mapping interface. Testing on territories ranging from 0.25 to 8.5 km² showed calculation accuracy within 2% error compared to manufacturer specifications and route generation time under 500ms. Performance evaluation demonstrated efficient handling of complex polygons with up to 1000 flight lines. The open-source system can be used for cartography, agricultural monitoring, infrastructure inspection, construction site monitoring, and environmental assessment tasks requiring aerial photography of large areas with high-resolution imagery and precise overlap for photogrammetric processing.

Keywords — UAV, unmanned aerial vehicles, route planning, aerial photography, GIS, lawnmower algorithm, boustrophedon, web application, photogrammetry, terrain following, microservices, geospatial analysis.
